Software & Docker architecture

  • Physics: SOFA Framework, run headless (no GUI) via the SofaPython3 bindings -- a rigid cube (Rigid3d MechanicalObject) with a corner-mapped PlaneForceField floor.
  • Backend: Python + FastAPI/Uvicorn. The physics loop runs in a background thread, integrating at the fine physics timestep below and broadcasting a throttled snapshot over a WebSocket (/ws/sim). REST endpoints handle reset/pause/parameters/CSV export.
  • Frontend: plain JS, no build step -- three.js for the 3D view and Chart.js for the live graphs, both loaded from a CDN.
  • Container: built on the official sofaframework/sofa_nightly_ubuntu:v24.06-standard image (which ships SOFA + SofaPython3 but not a usable libpython3 or working PYTHONPATH out of the box -- both are fixed up in the Dockerfile). One container per simulation serves the static frontend, REST API, and WebSocket together on port 8000; the MultiSimDocker orchestrator starts these containers on demand and proxies them under /sim/<id>/.
